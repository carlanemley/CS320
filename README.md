# Reflection
Working through the projects in this course helped me understand how to make sure my code is both functional and secure. I learned that the best way to ensure functionality is to test early and often. Writing unit tests in JUnit forced me to think about edge cases, invalid inputs, and how each method should behave before I even ran the program. This approach helped me catch issues quickly and gave me confidence that my code worked the way it was supposed to. I also learned that secure code often comes from the same mindset. Validating inputs, preventing invalid states, and writing tests that intentionally try to break the program all contribute to building software that is safer and more reliable.

Interpreting user needs was another major part of these projects. I realized that understanding requirements is not just about reading a list of features. It’s about breaking those features down into small, testable pieces and making sure the program behaves the way a real user would expect. Creating user stories helped me think from the user’s perspective and translate those needs into clear methods, classes, and tests. This made the development process more organized and helped me stay focused on what the program actually needed to do.

When it comes to designing software, I’ve learned that planning and structure matter just as much as writing the code itself. Starting with simple designs, identifying the core classes, and thinking about how they interact made the development process smoother. Writing tests alongside the code also shaped my design decisions, because it encouraged me to write smaller, more modular methods that were easier to test. Overall, my approach to software design has become more intentional, more organized, and more focused on long‑term maintainability.
